# Proxify CLI & Docker Gateway

Универсальное и безопасное решение для прозрачного проксирования трафика отдельных консольных приложений (включая утилиты на Go/Rust) на Linux (Ubuntu/Debian) без изменения системного шлюза.

Решает проблему статического связывания сетевых библиотек, которые игнорируют стандартные переменные окружения (`HTTP_PROXY`, `HTTPS_PROXY`) и механизмы `LD_PRELOAD` (например, `proxychains`).

---

## Архитектура и используемые технологии

В основе решения лежит комбинация сетевых пространств имен (Network Namespaces) и виртуального туннелирования:

```text
[Консоль хоста]
       │
       ▼ (запуск через proxify)
┌─────────────────────────────────────────┐
│ Firejail Network Namespace              │
│  - Полный доступ к файлам хоста         │
│  - Изолированный сетевой стек           │
└──────┬──────────────────────────────────┘
       │
       ▼ (виртуальный мост Docker br-xxxx)
┌─────────────────────────────────────────┐
│ Docker-контейнер (local-proxy-gw)       │
│  - tun0 (виртуальный TUN-интерфейс)      │
│  - iptables (NAT/Masquerade)            │
│  - tun2socks (перенаправление в прокси) │
└──────┬──────────────────────────────────┘
       │ (Внешнее SOCKS5/HTTP соединение)
       ▼
[Ваш Внешний Прокси] ──> [Интернет]
```

### Сторонние приложения:
1. **[Docker](https://www.docker.com/)** — изолирует шлюз маршрутизации. Запускается в безопасном режиме (`cap_add: [NET_ADMIN]`, без `privileged`).
2. **[tun2socks](https://github.com/xjasonlyu/tun2socks)** — принимает весь IP-трафик из виртуального интерфейса `tun0` внутри контейнера и пересылает его во внешний SOCKS5/HTTP прокси.
3. **[Firejail](https://firejail.wordpress.com/)** — создает легковесную сетевую песочницу для запускаемого приложения на хосте, подключая его напрямую в виртуальный мост Docker-сети и переопределяя дефолтный шлюз на IP-адрес контейнера-шлюза.

## Быстрый старт

### 1. Настройка `.env`
Создайте файл `.env` в корне проекта на основе образца `.env_sample`:
```ini
PROXY_TYPE=socks5  # http / socks5
PROXY_IP=127.0.0.1  # IP, домен или localhost (автоматически перенаправит на хост)
PROXY_PORT=1080

# Аутентификация (оставьте пустыми, если прокси без пароля)
PROXY_USER=
PROXY_PASS=
```

### 2. Установка
Запустите инсталлятор от имени администратора. Скрипт установит зависимости (`firejail`, `curl`, `unzip`), скачает `tun2socks` на хост, соберет образ и настроит псевдоним `proxify` в `.bashrc`/`.zshrc`:
```bash
chmod +x install.sh
sudo ./install.sh
```

Обновите конфигурацию текущего терминала:
```bash
source ~/.bashrc
```

### 3. Использование
Добавьте префикс `proxify` перед любой командой, которую необходимо выполнить через прокси:
```bash
# Проверка внешнего IP
proxify curl ifconfig.me

# Запуск Go/Rust утилит
proxify ./my-go-binary --option value
```

## Управление
* **Логи подключения (дебаг):** `docker logs -f local-proxy-gw`
* **Остановка шлюза:** `docker compose down`
* **Запуск шлюза:** `docker compose up -d`

---

## Ограничения
* **Только консольные утилиты:** Решение не поддерживает запуск GUI-приложений (например, VS Code или браузеров). Из-за конфликтов песочниц (Chromium/Electron sandbox), изоляции графического сервера (X11/Wayland) и клиент-серверной архитектуры, такие приложения либо не запустятся, либо пустят трафик в обход прокси. Для GUI-приложений используйте их встроенные настройки прокси.
